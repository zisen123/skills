Jira MCP Server

通过 HTML 页面抓取实现的 Jira MCP Server，让 Claude Code 能够操作 Jira。

背景

公司 Jira（v8.13.11，https://jira.sophgo.com）的 REST API 被完全封锁（rate-limit=0，永久 429）。但 Web 页面正常访问，且是服务端渲染的 HTML，包含完整的结构化数据。

本项目通过 Session Cookie 认证 + HTML 解析 绕过 API 限制，提供 MCP（Model Context Protocol）接口供 Claude Code 调用。

架构

Claude Code ──stdio──▶ MCP Server (Node.js) │ ▼ JiraClient ├── POST /rest/auth/1/session → JSESSIONID ├── GET /issues/?jql=... → 搜索结果 HTML ├── GET /browse/KEY-123 → Issue 详情 HTML └── POST /secure/*.jspa → 写操作 (带 atl_token) │ ▼ Cheerio HTML Parser → 结构化数据

涉及文件

文件作用
server.jsMCP 入口：注册工具（tools/list）、分发调用（tools/call），通过 stdio 与 Claude Code 通信
jira-client.js核心实现：登录、会话/XSRF cookie 管理、HTML 抓取与解析、各操作（search/get/comment/transition/assign/create）
project-id-cache.json项目 key→pid 缓存（已 gitignore，运行时自动生成/补全）
.mcp.json.exampleMCP 配置模板，复制到项目根目录后填入凭据
package.json依赖声明（@modelcontextprotocol/sdk、cheerio）

认证流程

  1. 启动时用 username/password 调用 /rest/auth/1/session 获取 JSESSIONID
  2. 后续请求通过 Cookie: JSESSIONID=xxx 认证
  3. Session 过期（401 或 302 到登录页）时自动重新登录
  4. 写操作从页面提取 atl_token 用于 XSRF 防护；request() 还会自动捕获并回传 atlassian.xsrf.token cookie（创建 issue 等表单提交需要）

创建 issue 的实现细节

该实例的 REST createmeta 接口同样被封锁，无法用常规方式查询项目 ID（pid）和 issue 类型，因此 jira_create_issue 完全基于 HTML 表单实现，关键点如下：

  • pid 反查：访问 /secure/CreateIssueDetails!init.jspa?pid=N，页面里 description 文本框带有 data-projectkey="KEY" 属性，据此把项目 key（如 CV184XSDK）映射到数字 pid。遍历探测命中后写入磁盘缓存 project-id-cache.json，途经的所有 key→pid 一并缓存，所以全量扫描一辈子只发生一次。
  • issue 类型：内置常见类型名到 id 的映射（故障/Bug=10100、任务/Task=10002、故事=10001、改进=10200、子任务=10103），也可直接传数字 id。
  • XSRF 防护：提交时需同时携带三样东西 —— 请求头 X-Atlassian-Token: no-check + 同 session 的 atlassian.xsrf.token cookie（由 request() 自动捕获并回传）+ 表单里的 atl_token/formToken，缺一不可。
  • 必填字段：reporter（报告人）为必填，缺省取登录用户；priority 部分项目必填，缺省取表单默认值（Medium）。
注意：pid 与 issue 类型是实例 / 项目相关的，不同 Jira 实例的数值不同。project-id-cache.json 已被 gitignore，预置了若干常用项目（如 CV184XSDK=10716、CV180X181X=10414），缺失项目首次创建时会自动探测补全。

使用方法

1. 安装依赖

cd mcp/jira-mcp-server
npm install

2. 配置 MCP Server

复制模板到你的项目根目录：

cp mcp/jira-mcp-server/.mcp.json.example /your/project/.mcp.json

编辑 .mcp.json，填入实际信息：

{
  "mcpServers": {
    "jira": {
      "command": "node",
      "args": ["/absolute/path/to/mcp/jira-mcp-server/server.js"],
      "env": {
        "JIRA_URL": "https://jira.sophgo.com",
        "JIRA_USER": "your_username",
        "JIRA_PASSWORD": "your_password"
      }
    }
  }
}
安全提示：.mcp.json 包含密码，务必：
  • 设置文件权限：chmod 600 .mcp.json
  • 加入 gitignore 防止提交

3. 使用

配置好后需重启 Claude Code，让它重新加载 MCP server（新增工具同理）。之后在 Claude Code 中直接用自然语言操作 Jira：

  • "搜索我最近的未关闭 issue"
  • "查看 CV184XSDK-1299 的详情"
  • "给 IVA-1114 添加评论：已完成测试"
  • "把这个 issue 指派给 zhang.san"
  • "在 CV184XSDK 创建一个故障：xxx 编译失败，描述是 ……"
验证 server 是否正常：不进 Claude Code 也能用一条命令握手测试： 
echo '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"t","version":"1.0.0"}}}' \
  | JIRA_URL=https://jira.sophgo.com JIRA_USER=xxx JIRA_PASSWORD=xxx node server.js
返回带 serverInfo 的 JSON 即说明启动正常。

技术栈

  • Runtime: Node.js（ES Modules）
  • MCP SDK: @modelcontextprotocol/sdk
  • HTML 解析: cheerio
  • 传输: stdio（Claude Code 标准方式）

已知限制

  • 依赖 Jira 页面的 HTML 结构，Jira 升级可能需要更新选择器
  • Session 有效期有限（通常几小时），但已实现自动续期
  • 搜索结果依赖 splitview 或 table 两种页面布局，已做兼容
  • 创建 issue 时，若目标项目不在 project-id-cache.json 缓存里，首次会遍历探测 pid（约上百次请求），命中后写入缓存，后续即时返回
